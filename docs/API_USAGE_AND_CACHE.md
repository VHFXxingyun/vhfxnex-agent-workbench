# API 用量与缓存命中说明

更新时间：2026-11-14

本说明用于区分 DeepSeek 返回的缓存遥测、VHFXNEX 派生的命中指标和当前价费用估值。费用最终以 DeepSeek 开放平台账单为准。

## 三个缓存指标

| 指标              | 计算方式                                                  | 适合回答的问题               |
| ----------------- | --------------------------------------------------------- | ---------------------------- |
| 命中请求率        | 至少命中 1 个输入 Token 的请求数 ÷ 已返回缓存统计的请求数 | 有多少请求复用过缓存？       |
| 输入 Token 命中率 | 缓存命中输入 Token ÷ 已返回缓存统计的输入 Token           | 被统计的输入里有多少被复用？ |
| 统计覆盖率        | 已返回缓存统计的输入 Token ÷ 全部输入 Token               | 命中率覆盖了多少实际输入？   |

命中请求率不等于省钱比例。例如 100 次有遥测的请求里 50 次各命中 1 Token，请求命中率是 50%；如果总输入有 100,000 Token，输入 Token 命中率却只有 0.05%，省下的输入费很少。反过来，一次长请求命中大部分输入，命中请求率可能很低，但被复用的 Token 数和节省会较大。

没有缓存字段的请求不会被算成未命中，也不会放进前两个指标的分母；其输入仍进入覆盖率分母。因此解读命中率时，应先看统计覆盖率。低覆盖时，命中率只能代表那部分有遥测的请求。

## DeepSeek 缓存和计费

DeepSeek 自动进行上下文缓存，匹配的是从输入起始位置开始、完全相同的前缀单元，不是语义相似的内容。第一次请求可能只建立缓存；缓存需要时间持久化，并按 best-effort 提供，既不保证命中，也可能在数小时到数天后清理。详情见 [DeepSeek 上下文缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)。

截至本说明日期，官方 DeepSeek V4.1 Flash 公开单价（美元/百万 Token）如下。具体高峰时段与节假日规则以[官方价格表](https://api-docs.deepseek.com/quick_start/pricing/)为准。

| Token 类型     | 非高峰 |   高峰 |
| -------------- | -----: | -----: |
| 输入缓存命中   | $0.003 | $0.006 |
| 输入缓存未命中 |  $0.15 |  $0.30 |
| 输出           |  $0.60 |  $1.20 |

因此，每个被缓存命中的输入 Token 在此价格表下比未命中便宜 50 倍，即少付约 98% 的该 Token 输入费。缓存只影响输入 Token；输出 Token 仍按输出价计费。供应商报告的思考 Token 是输出 Token 的组成部分，不能重复相加。DeepSeek 的 Search / Fetch 工具若被调用，还会按成功请求另行收费；VHFXNEX 当前使用自己的网页搜索适配器时，不应把这项费用自动套到应用搜索上。

按已知用量计算时：

```text
当前价输入/输出费用 ≈
(命中输入 Token × 命中单价
 + 未命中输入 Token × 未命中单价
 + 输出 Token × 输出单价) ÷ 1,000,000
```

如果缓存字段缺失、模型不在当前价格表内，或历史价格与当前价格不同，就不能从 Token 总量精确还原历史扣款。VHFXNEX 管理页面显示的是当前价估值区间，不是历史账单；实际金额、汇率和赠送额度以供应商控制台为准。

## VHFXNEX 的受控测量样本

2026-11-14 的 17 次受控直接 API/SDK 前缀探测中，9 次至少命中 1 个输入 Token，命中请求率为 52.9%；合计 7,891 个输入 Token 中有 3,456 个命中，输入 Token 命中率为 43.8%。按非高峰输入价估算，这 3,456 个命中 Token 相较全部未命中约少付 $0.00051；高峰价约少付 $0.00102。

这是小样本前缀探测，只说明那组相同前缀在该次测试中可复用，不代表完整浏览器工作流、之后的真实账号使用或长期命中率，也不能推算用户的整月账单。冷启动、新账号、不同账户、提示前缀变化、上下文中较早内容变化以及缓存过期都会影响命中。

## 在应用里查看

管理员可打开“管理控制台 → AI 调用趋势 → 按 Agent 来源查看用量与缓存”。先看统计覆盖率，再比较命中请求率和输入 Token 命中率，并按规划、对话、工作台和代码复核来源检查输入/输出 Token。若关注费用，还要看输入与输出分别占多少；只有命中请求率不足以解释费用。

应用只保存 Token 数、缓存统计、模型、请求耗时及来源，不保存提示词或思考文本。跨账户缓存按稳定伪名隔离：这有利于隐私，但减少了不同账户偶然复用同一前缀的机会。项目在规划、对话、工作台和代码复核 Agent 前共享静态提示前缀，尽量让同一账户的固定规则可复用；是否实际命中仍以供应商返回的缓存字段为准。
